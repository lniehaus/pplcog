# pplcog: adaptive centre-of-gravity control for push-pull locomotion rovers

Code, parameter tables and result files of the article

> J. Schöning, Q. He, L. Niehaus and K. Iizuka, *Adaptive Center of Gravity Control for
> Push-Pull Locomotion Rovers on Slopes: A Cross-Domain Framework Linking Planetary
> Exploration with Agricultural Automation*, submitted to Frontiers in Control Engineering, 2026.

The package has two parts. `pplcog` evaluates the quasi-static centre-of-gravity (CoG) model,
Equations (1) to (5) of the article, for a push-pull locomotion (PPL) rover with a longitudinally
movable mass whose masses, actuator limits and phase duration are not yet measured. `pplcog.sim`
is the closed-loop pitch-plane simulation that forms step one of the article's validation
protocol. Every parameter carries a source tag (photo, sibling rover, literature, assumed,
manuscript, study); the two parameter tables with their provenance are
[`docs/parameters_model_evaluation.md`](docs/parameters_model_evaluation.md) and
[`docs/parameters_simulation.md`](docs/parameters_simulation.md). They were Tables 3 and 2 of the
first submission and are the files the article's Data Availability Statement refers to.

The code was written by the authors with the assistance of a generative AI coding tool
(Claude Code, Anthropic). Every model equation, parameter value and result was checked by the
authors against the sources cited in the article and in the parameter tables.

## Installation

Requires Python 3.13 or newer and [uv](https://docs.astral.sh/uv/).

```
uv sync
uv run pytest -q      # 25 tests, about half a minute
```

## Reproduction

| Command | What it does | Time |
|---|---|---|
| `uv run pplcog` | model evaluation: Figure 4, `results.json`, parameter table | seconds |
| `uv run pplcog-sim --quick` | reduced simulation study for development (`*_quick` outputs) | a few minutes |
| `uv run pplcog-sim` | full simulation study: Figures 5 and 6, Tables 2 and 3, `results_sim.*` | about 100 min on 12 cores |
| `uv run pplcog-sim --rail-start 0.182` | secondary rail placement | as above |

`make`, `make sim`, `make sim-quick`, `make test` and `make clean` wrap these commands.

All outputs go to `out/`. Both studies are seeded (`Study.seed = 20261001` in `pplcog/params.py`,
`SimParams.seed = 20261002` in `pplcog/sim/params_sim.py`), and the dependency versions are pinned
in `uv.lock`, so a run reproduces the tracked result files up to floating-point noise of the BLAS
library. Each run also rewrites its tracked parameter table in `docs/`; the simulation does so in the
full run only.

Expensive steps of the simulation are cached in `out/cache/` with joblib. The cache is keyed on the
parameters and on what was learned, not on the source code: after editing the simulation code,
run with `--no-cache` or delete `out/cache/`. `--n-jobs` limits the worker count.

## Tracked result files

The result files in `out/` are tracked in this repository; the cache, logs, `*_quick` outputs and the
`*_rail…` outputs of `--rail-start` are not. All tracked files but `figS1` are used by the article. The
file names carry the figure numbers of the first submission, which
differ from the published numbering:

| File | Article |
|---|---|
| `out/fig5a.pdf` to `out/fig5d.pdf` (and `.png`) | Figure 4(a) to (d), model evaluation |
| `out/fig6a.pdf` to `out/fig6d.pdf` (and `.png`) | Figure 5(a) to (d), simulation results |
| `out/fig6e.pdf` (and `.png`) | Figure 6, Stage C rule from the Gaussian process |
| `out/figS1.pdf` (and `.png`) | not in the article: drawbar pull and torque versus slip and sinkage versus load of the Wong-Reece wheel model for the nominal soil, a check of the wheel-soil tables |
| `out/results.json` | key numbers of the model evaluation: slope ranges, sensitivities, envelopes, actuator-loop ratios |
| `out/results_sim.json`, `out/results_sim.csv` | simulation metrics per condition, slope and soil; steepest slopes; bound checks; paired statistics (Tables 2 and 3); Stage C rule numbers |
| `out/params.md`, `out/params_sim.md` (`.tex` twins) | parameter tables as written by the runs (tracked legend copies: `docs/`) |
| `out/models/stageA.joblib`, `out/models/stageC.joblib` | fitted Stage A classifier and set-point table, fitted Stage C Gaussian process |

The simulation metrics and statistics appear twice in `results_sim.json`, once for the `protocol` set and
once for the `all_test` set. Since the twenty repetitions of the protocol are all twenty held-out soils,
the two sets are identical.

`out/model_evaluation_snippet.tex` and `out/simulation_snippet.tex` are drafts of the manuscript
text with the numbers filled in; they are regenerated by the runs and not tracked.

## Model evaluation (`pplcog/`)

| Module | Role |
|---|---|
| `params.py` | dataclasses `Rover`, `Soil`, `Actuator`, `Study`; provenance registry |
| `frame.py` | rail-fixed and rear-contact frames, wheelbase per phase, chassis CoG, CoG height |
| `statics.py` | Eqs. (1) to (3), feasibility, slope range, Eq. (5) envelope, rail room |
| `terramechanics.py` | Bekker sinkage and resistance, thrust limit, traction utilisation, soil sampling |
| `actuator.py` | Eq. (4) with rate and acceleration limits, PI variants, bounded offset, bound check |
| `sweeps.py` | data for the four panels and the key numbers |
| `plotting.py` | panels as PDF and PNG |
| `report.py` | tables, JSON, snippet |
| `run_all.py` | entry point `pplcog` |

Modelling decisions:

- Rail and chassis fixed to the rear pair by default (`Rover.rail_on`); the front-pair
  variant flips the sign of dN_F/dL, which is reported in `results.json`.
- The rail is parallel to the chassis axis, so the CoG height does not depend on the mass
  position; it depends on the mass fraction through the rail height.
- Both N_F >= N_min and N_R >= N_min are enforced.
- The utilisation-optimal set point equals the unit load ratio for identical wheel pairs
  and is independent of the soil parameters; the soil Monte Carlo confirms this.
- Absolute masses enter only the terramechanics part; the statics are dimensionless.

To update for measured rover values, change the defaults in `params.py` and rerun.

## Closed-loop simulation (`pplcog/sim/`)

A pitch-plane dynamic simulation with a Wong-Reece wheel-soil model, randomised silica-sand
parameters, the PPL phase machine, the rail actuator, three baselines (wheel driving, PPL with
the mass centred, PPL with the physics-based set point) and Stages A and C of the controller.
Stage B is not evaluated.

| Module | Role |
|---|---|
| `sim/params_sim.py` | `SoilWR` (Wong-Reece extras on top of `Soil`), `SimParams`, provenance |
| `sim/wheel_soil.py` | stress integration, per-soil (sinkage, slip) tables, bulldozing resistance |
| `sim/rover.py` | two-unit pitch-plane dynamics, anchor element, load transfer, torque limit |
| `sim/locomotion.py` | phase machine, wheelbase profile, wheel speed command |
| `sim/cog_controllers.py` | rail actuator, baselines, Stage A and Stage C controllers |
| `sim/features.py` | per-cycle proprioceptive features with noise, per-cycle metrics |
| `sim/simulate.py` | `run_episode` |
| `sim/learning.py` | soil population, terrain classes, Stage A and Stage C fitting (Stage A falls back to the physics set point where fewer than three training soils complete) |
| `sim/interpret.py` | partial dependences of the Stage C Gaussian process per phase type, rule numbers (Figure 6) |
| `sim/experiment.py` | evaluation matrix, steepest slope, bound check, paired statistics |
| `sim/plots_sim.py`, `sim/report_sim.py`, `sim/run_sim.py` | figures, tables, snippet, entry point `pplcog-sim` |

If a directory `../paper/figures` exists next to this repository, the full runs also copy the
figure PDFs there; otherwise this step is skipped.
